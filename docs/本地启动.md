# InterviewMaster 本地启动指南

> 本文档于 2026-08-14 在 Windows 11、PowerShell、Docker Desktop 环境完成实际启动验证。当前数据库版本为 v9，产品主流程为“上传简历 → 选择语言和目标公司 → 直接开始后端模拟面试 → 查看完整面试记录”。

## 1. 服务与地址

| 服务 | 作用 | 本地地址 |
| --- | --- | --- |
| Web | Next.js 产品前端 | <http://localhost:3000> |
| API | go-zero REST API | <http://localhost:8080> |
| PostgreSQL + pgvector | 业务数据、简历事实与面试记录 | `localhost:5432` |
| Redis | Asynq 任务队列 | `localhost:6379` |
| MinIO | 简历和音频对象存储 | API `localhost:9000`；控制台 <http://localhost:9001> |
| Tika | PDF、DOCX、文本简历解析 | `localhost:9998` |
| Worker | 简历解析、面试准备和报告生成 | 无公开端口 |
| Whisper ASR（可选） | Beta 语音转写 | `localhost:9002` |

## 2. 前置要求

- Docker Desktop 已启动，并能执行 `docker ps`。
- 根目录存在 `.env`；首次启动时从 `.env.example` 复制。
- 只有执行迁移、代码生成或混合开发时才需要本机 Go、Node.js 和 pnpm。

```powershell
Copy-Item .env.example .env
```

不要把真实模型密钥、数据库密码或对象存储密钥提交到 Git。

## 3. 首次启动或升级

### 3.1 启动基础设施

在项目根目录执行：

```powershell
docker compose up -d postgres redis minio tika
docker compose ps
```

PostgreSQL 和 Redis 应显示 `healthy`。

### 3.2 从 v8 升级前备份

迁移 `00009_launch_redesign.sql` 会删除旧 JD 表。已有本地数据时应先备份：

```powershell
New-Item -ItemType Directory -Force .cache/backups | Out-Null
docker exec interviewmaster-postgres-1 sh -c 'pg_dump -U "$POSTGRES_USER" -d "$POSTGRES_DB" -Fc -f /tmp/before_v9.dump'
docker cp interviewmaster-postgres-1:/tmp/before_v9.dump .cache/backups/before_v9.dump
```

本次实际升级生成的备份是：

```text
.cache/backups/before_launch_redesign_20260814_0147.dump
```

### 3.3 执行数据库迁移

`goose` 不会自动读取根目录 `.env`。将下面的连接串替换为 `.env` 中实际使用的用户、密码和数据库名：

```powershell
cd backend
$env:IM_DATABASE_URL = "postgres://<POSTGRES_USER>:<POSTGRES_PASSWORD>@localhost:5432/<POSTGRES_DB>?sslmode=disable"
go run github.com/pressly/goose/v3/cmd/goose@v3.27.1 -dir migrations postgres $env:IM_DATABASE_URL up
cd ..
```

检查迁移状态：

```powershell
cd backend
go run github.com/pressly/goose/v3/cmd/goose@v3.27.1 -dir migrations postgres $env:IM_DATABASE_URL status
cd ..
```

最新版本应为 `00009_launch_redesign.sql`。

## 4. 推荐启动方式：全容器模式

首次构建或代码发生变化时：

```powershell
docker compose --profile app up -d --build api worker web
```

日常重新启动已有镜像：

```powershell
docker compose --profile app up -d
```

查看状态：

```powershell
docker compose --profile app ps
```

正常情况下应看到以下服务运行：

- `postgres`、`redis`、`minio`、`tika`
- `api`、`worker`、`web`

Web 镜像使用 Next.js standalone 运行模式；`.dockerignore` 会排除本机的 `node_modules`、`.next` 和缓存目录，避免 Windows 依赖覆盖容器依赖。

## 5. 启动验证

PowerShell：

```powershell
Invoke-WebRequest -UseBasicParsing http://localhost:8080/api/v1/health
Invoke-WebRequest -UseBasicParsing http://localhost:8080/api/v1/ready
Invoke-WebRequest -UseBasicParsing http://localhost:3000/
Invoke-WebRequest -UseBasicParsing http://localhost:3000/api/v1/health
```

预期结果：

- API `/health` 返回 HTTP 200。
- API `/ready` 返回 HTTP 200，且 `database`、`redis` 均为 `ok`。
- Web 首页返回 HTTP 200。
- 通过 Web 访问 `/api/v1/health` 同样返回 HTTP 200，证明容器内部代理正常。

浏览器打开 <http://localhost:3000>，注册或登录后即可使用。

## 6. 日志与故障排查

查看最近日志：

```powershell
docker compose logs --tail 100 api worker web
```

持续跟踪：

```powershell
docker compose logs -f api worker web
```

只重建某个服务：

```powershell
docker compose --profile app up -d --build api
docker compose --profile app up -d --build worker
docker compose --profile app up -d --build web
```

如果 Web 首页正常但 `/api/v1/*` 返回 500，确认 Web 镜像是最新版本，然后重新构建：

```powershell
docker compose --profile app up -d --build web
```

## 7. 混合开发模式

需要代码热更新时，可以只用 Docker 运行基础设施，在三个终端分别启动应用。

先把根目录 `.env` 加载到当前 PowerShell 进程：

```powershell
Get-Content .env | ForEach-Object {
    if ($_ -match '^\s*([^#][^=]*)=(.*)$') {
        $name = $matches[1].Trim()
        $value = $matches[2].Trim().Trim('"').Trim("'")
        Set-Item -Path "Env:$name" -Value $value
    }
}
```

然后分别运行：

```powershell
# 终端 1：API
cd backend
go run -buildvcs=false ./apps/api -f apps/api/etc/interviewmaster.yaml

# 终端 2：Worker
cd backend
go run -buildvcs=false ./apps/worker -f apps/worker/etc/worker.yaml

# 终端 3：Web
pnpm --dir web dev
```

不要在全容器模式仍占用 3000、8080 端口时重复启动本机 Web 或 API。

## 8. AI 模式

默认 `IM_AI_ENABLED=false`，无需模型密钥也能完成本地闭环：Worker 使用规则候选题，面试推进采用确定性降级，报告使用降级评分。

启用模型时在 `.env` 配置：

```dotenv
IM_AI_ENABLED=true
IM_AI_PROVIDER=openai-compatible
IM_AI_BASE_URL=https://api.openai.com/v1
IM_AI_API_KEY=替换为真实密钥
IM_AI_CHAT_MODEL=gpt-4.1-mini
IM_AI_REQUEST_TIMEOUT=30s
IM_AI_MAX_OUTPUT_TOKENS=4096
IM_AI_STRUCTURED_OUTPUTS=true
```

启用后：

- Worker 根据简历版本快照、主语言、固定后端岗位和目标公司生成内部蓝图与候选题。
- 用户回答后，API 面试官节点在追问、切换考点和结束之间进行有界决策。
- 面试完成后 Worker 逐轮评分并生成完整复盘。

内部候选题和通用异步任务不会作为前端管理模块暴露。

## 10. 停止与恢复

只停止应用层，保留基础设施：

```powershell
docker compose --profile app stop api worker web
```

重新启动应用层：

```powershell
docker compose --profile app start api worker web
```

停止全部容器但保留数据库卷：

```powershell
docker compose --profile app down
```

不要执行 `docker compose down -v`，除非明确希望删除全部本地数据库和对象存储数据。
