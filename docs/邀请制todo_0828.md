## 1. P0 门禁：陌生人进不来

现状：`POST /api/v1/auth/register` 对任意合法邮箱开放；官网「免费开始」直达 `/register`。`registerlogic.go` 只校验邮箱/密码/显示名并 bcrypt 入库。

三选一即可，推荐 **方案 A**（名称就是邀请制）。做完一种就不要并行三种。

### 1.1 方案 A：邀请码（推荐）

- [ ] 邀请码表：码、创建者、过期时间、可用次数或一次性、已用次数、可选绑定邮箱。
- [ ] `POST /auth/register` 增加必填 `invite_code`；无效/过期/用尽返回明确错误，不泄露「码是否存在」以外的细节。
- [ ] 使用成功后在同一事务里扣次数，避免并发超发。
- [ ] 前端 `/register` 增加邀请码输入；营销页「免费开始」改为「已有邀请码？注册」或隐藏公开 CTA。
- [ ] 本地/种子：文档写清如何插入第一枚码（SQL 或管理脚本）。生产码不进仓库。
- [ ] 测试：无码、错码、过期、用尽、正确码注册成功、同一码并发。

### 1.2 方案 B：关闭公开注册（人极少时更快）

- [ ] 配置项例如 `IM_REGISTER_ENABLED=false`（生产默认关）。
- [ ] 关闭时 `POST /auth/register` 返回固定业务错误；`/register` 页说明「目前仅邀请，请联系管理员」。
- [ ] 用一次性脚本或 SQL 创建受邀用户（密码哈希与线上一致）。
- [ ] 文档写清开户步骤；不要把明文密码写进 Git。

### 1.3 方案 C：邮箱白名单

- [ ] 仅白名单邮箱可注册；适合名单极短且几乎不变的情况。
- [ ] 名单走环境变量或表，不要写死在前端。

门禁验收：未持码/未在名单的请求在 API 与 UI 都被拒绝；已有账号仍可登录。

## 3. P1 证明：CI 能拦住回归

邀请制可以先靠第 2 节手工跑，但 Prompt/状态机一改就容易无声坏掉。按收益排序：

### 3.1 Golden 作为门禁，而不是「有测试文件」

现状：`backend/internal/aieval` 等已有 Fake Model + `testdata/golden/v1`；CI 已 `go test ./...`。缺的是「低于约定基线就不让合」的硬门，以及真实 Provider 样本。

- [ ] 约定邀请制最低集：空回答、跑题、Prompt Injection、正常深挖、建议结束被状态机否决。失败必须是明确错误或受控降级，不能改写业务状态机。
- [ ] 把该包测试保持在 CI 必跑路径（已有则只补缺口样本，不要再平行造一套）。
- [ ] **不做**：大规模人工标注对照集（公开注册后再说）。

### 3.2 Worker 集成（真 PG + Redis + 队列）

现状：大量单测；缺少重复投递、崩溃重放、幂等、死信的集成测试。

- [ ] 最小集成：`interview:prepare` 成功一次；同一 payload 重放不重复插入第一题。
- [ ] 最小集成：`interview:next_turn` Ack 前崩溃再投递，不出现重复 Turn。
- [ ] 可用 Compose 测试库或 CI service container；不要在单测里假装队列。

### 3.3 Playwright 主路径（可用规则模式）

现状：`web/e2e/marketing.spec.ts` 只覆盖官网文案和未登录跳转 `/login`。CI **没有**跑 Playwright。

- [ ] 规则模式或 Mock：注册（含邀请码，若已做 1.1）→ 登录 → 上传简历（或夹具）→ 进入面试间看到第一题。
- [ ] 提交一轮回答后出现 deciding → 下一问或明确失败重试。
- [ ] 不要求 CI 每次打真实模型（贵、不稳）。真模型留在第 2 节或可选 smoke。

### 3.4 可选：真实 Provider smoke

- [ ] 单独 job 或手工脚本，密钥只来自 CI Secret / 本机环境。
- [ ] 断言准备 + 至少一轮 next_turn 的 `model_invocations` 不为 0。
- [ ] 失败不阻断普通 PR（邀请制阶段），但发版前要跑。
