# InterviewMaster 前端重构需求规格

> 文档状态：已确认，可用于方案设计与开发拆分  
> 更新时间：2026-07-29  
> 适用范围：InterviewMaster Web 前端及其依赖的后端接口补充

## 1. 文档目的

当前前端只有一个集中式工作台页面，能够验证主要后端流程，但在信息架构、视觉体验、交互完整性、移动端适配和工程可维护性方面尚未达到正式产品标准。

本次重构的目标是将现有验证型页面升级为面向真实用户的完整 Web 产品。本文件作为后续 UI 设计、前端开发、后端接口补充和验收的统一需求依据。

本阶段只产出重构规格，不直接修改现有前后端实现。

## 3. 产品目标

### 3.1 用户目标

- 新用户能快速理解产品价值并完成注册。
- 用户能清楚地完成简历上传、解析和查看。
- 用户能保存职位描述，并基于简历和可选 JD 生成面试题。
- 用户能在具有真实节奏感的界面中逐题完成模拟面试。
- 用户能通过结构化报告理解优势、问题和下一步训练方向。
- 用户在桌面端和移动端都能顺畅完成核心流程。

### 3.2 业务目标

- 将项目从技术演示页面升级为可持续迭代的产品界面。
- 建立清晰的页面体系、设计系统和组件边界。
- 为后续语音面试、公司面试信息和更多 AI 能力预留扩展空间。
- 让前后端接口差距可追踪、可分阶段交付。

### 3.3 工程目标

- 保留 React 作为前端开发核心。
- 使用 Next.js App Router 承载官网、产品路由和渲染能力。
- 统一 API 调用、服务端状态、表单验证、错误反馈和加载状态。
- 将当前单文件页面拆分为可测试、可复用的业务模块。
- 继续以 `backend/api/interviewmaster.api` 及其生成类型作为接口契约基础。

## 4. 非目标

以下内容不进入第一阶段重构：

- 公司面试信息 Beta 功能的正式产品化。
- ASR 语音转写 Beta 功能的正式产品化。
- 实时语音面试、视频面试或数字人。
- 社区、职位投递、招聘方后台。
- 英文界面；工程结构可预留国际化能力，但第一期只提供中文。
- 简历与多个 JD 之间的复杂版本关系。
- 原生移动应用。

## 5. 产品原则

1. **一次只强调一个主要动作**：每个页面都应有清晰的主任务和主按钮。
2. **复杂能力分步呈现**：上传、生成、面试等流程采用步骤化交互，不把所有功能堆在一个页面。
3. **状态始终可见**：解析中、生成中、已完成、失败等状态必须明确展示。
4. **结果可解释**：报告不仅给分数，还要展示依据、问题和可执行建议。
5. **移动端不是缩小版桌面端**：移动端重新安排导航、操作区和内容密度。
6. **避免伪能力**：后端不支持的操作不得做成看似成功的前端假交互。

## 7. 核心用户流程

### 7.1 首次使用

1. 用户访问官网并了解产品价值。
2. 用户进入注册页，填写显示名称、邮箱和密码。
3. 注册成功后自动登录并进入仪表盘。
4. 首次使用引导用户上传简历。
5. 简历解析期间显示任务进度和产品功能引导。
6. 解析完成后引导用户添加 JD 或直接填写目标岗位。
7. 用户生成题集并预览题目。
8. 用户创建模拟面试并逐题作答。
9. 用户提交整场面试并查看报告。

### 7.2 回访用户

1. 登录后进入仪表盘。
2. 继续未完成的面试，或从已有简历/JD 创建新训练。
3. 在面试历史中查看以往报告。
4. 根据改进建议开始下一轮训练。

### 7.3 简历上传与解析

1. 用户选择 PDF、DOCX 或 TXT 文件，前端校验文件类型和 20 MB 大小限制。
2. 前端请求上传凭证。
3. 前端将文件直接 `PUT` 到预签名地址，并显示上传进度。
4. 上传完成后通知后端启动解析。
5. 前端创建任务追踪状态。
6. 解析成功后跳转简历详情；失败时显示可理解的原因和重试入口。

## 8. 视觉与设计系统

### 8.1 品牌方向

- 产品名称：InterviewMaster。
- 中文副标题：AI 面试训练助手。
- 品牌气质：可信、克制、专业、友好。
- 不采用过度炫光、复杂渐变或游戏化视觉。
- 绿色只用于主操作、成功状态和少量品牌识别，不大面积铺色。

### 8.2 颜色建议

浅色主题：

- 页面背景：`#F7F7F8`
- 主表面：`#FFFFFF`
- 主文字：`#171717`
- 次级文字：`#6B7280`
- 边框：`#E5E7EB`
- 品牌色：`#10A37F`
- 危险色：`#DC2626`
- 警告色：`#D97706`

深色主题：

- 页面背景：`#171717`
- 主表面：`#212121`
- 次级表面：`#2F2F2F`
- 主文字：`#ECECEC`
- 次级文字：`#A3A3A3`
- 边框：`#3F3F46`
- 品牌色：`#19C37D`

最终颜色必须通过 CSS Variables 管理，组件内不得散落硬编码色值。

### 8.3 字体和排版

- 优先使用系统中文无衬线字体。
- 正文默认 14–16 px。
- 正文行高不低于 1.6。
- 页面标题、区块标题和正文最多使用三级视觉层级。
- 面试题正文应具有更大的字号和舒适行宽。

### 8.4 圆角和阴影

- 表单控件和按钮采用 8–10 px 圆角。
- 卡片采用 12–16 px 圆角。
- 主要依靠背景和边框区分层级，阴影保持轻量。
- 弹窗和浮层可以使用更明显但柔和的阴影。

### 8.5 主题切换

- 支持浅色、深色和跟随系统三个选项。
- 默认跟随系统。
- 用户选择持久化到本地。
- 切换主题时不闪烁、不丢失页面状态。

## 9. 页面级需求

### 9.1 产品官网

官网应包含：

- 顶部品牌、功能、使用流程、登录和免费开始入口。
- 首屏价值主张：“基于你的简历和目标岗位，完成可复盘的 AI 模拟面试。”
- 三步流程：准备材料、开始面试、获得报告。
- 核心能力介绍：简历理解、定制题集、逐题面试、复盘报告。
- 面向应届生和社招用户的使用场景。
- 页面底部 CTA 和基础页脚。

移动端首屏必须在不滚动过多的情况下看到核心价值和主 CTA。

### 9.2 登录与注册

- 登录字段：邮箱、密码。
- 注册字段：显示名称、邮箱、密码、确认密码。
- 表单提供即时校验、密码可见性切换和提交中状态。
- 登录失败时显示明确错误，不暴露敏感后台信息。
- 第一阶段不提供第三方登录和找回密码，相关入口不应伪装成可用。

### 9.3 仪表盘

仪表盘包含：

- “开始新训练”主按钮。
- 最近简历和最近 JD。
- 最近面试记录。
- 训练次数、平均分、最近趋势。
- 高频待改进方向。
- 正在执行或失败的异步任务。
- 新用户空状态和首次使用引导。

数据不足时使用真实空状态，不能使用虚构统计数字。

### 9.4 简历列表

- 显示标题、文件名、更新时间和解析状态。
- 支持按更新时间和状态筛选。
- 支持上传新简历、重命名、删除和重新解析。
- 解析中显示进度；解析失败显示原因及重试操作。
- 移动端改用纵向卡片，不强制保留桌面表格。

### 9.5 简历详情

- 展示标题、原始文件、版本、上传时间和解析状态。
- 按类别展示个人信息、教育经历、工作经历、项目经历、技能等事实。
- 每条事实可展示来源摘录，帮助用户判断解析准确性。
- 提供重命名、重新解析和删除操作。
- 删除操作必须二次确认。

### 9.6 JD 列表和详情

- 列表展示公司、岗位、能力标签和更新时间。
- 支持新建、查看、编辑和删除。
- 新建/编辑页字段为公司、岗位名称和 JD 正文。
- JD 正文输入区适合粘贴长文本，并显示字符数。
- 详情页突出后端提取的能力标签。

### 9.7 题集生成与详情

生成题集时：

- 简历必选。
- JD 可选。
- 目标岗位可选；未选择 JD 时建议填写。
- 提交前展示所选材料摘要。
- 生成中显示明确进度和可离开页面提示。

题集详情：

- 展示题目顺序、问题、考察意图、期望回答点和追问提示。
- 支持重新生成、删除和手动编辑题目。
- “开始模拟面试”为页面主操作。

简历与 JD 的长期关系尚未定稿，第一版不建立复杂绑定模型。

### 9.8 面试历史

- 分为进行中和已完成。
- 展示标题、关联题集、创建时间、完成状态、回答进度和总分。
- 进行中的面试可继续。
- 已完成的面试只能查看，不允许重新修改回答。
- 支持按状态和时间筛选。

### 9.9 创建面试

- 选择一个题集。
- 自动带出关联简历、JD 和题目数量。
- 可修改面试标题。
- 展示计时规则。
- 开始前明确提示：进入面试后计时不可暂停。

### 9.10 面试房间

页面采用专注模式，一次只显示一道题：

- 顶部显示退出入口、整场已用时间和总体进度。
- 主区域显示当前题目和必要的回答提示。
- 输入区提供多行文本输入。
- 底部提供“上一题”“跳过”“下一题/提交回答”。
- 侧边或抽屉展示题目导航和每题状态。
- 移动端底部操作区固定，题目导航使用抽屉。

题目状态：

- 未开始
- 作答中
- 已回答
- 已跳过

计时规则：

- 每题默认倒计时 3 分钟。
- 整场参考时长为题目数乘以 3 分钟。
- 顶部同时显示当前题剩余时间和整场已用时间。
- 当前题剩余 30 秒时给出视觉提醒。
- 单题超时后继续计时或显示超时状态，但不自动提交、不自动跳过。
- 整场面试开始后不能暂停。
- 页面刷新后计时应根据服务端开始时间恢复，不能重新计时。

跳过和重答规则：

- 跳过当前题后进入下一题，并将当前题标记为待回答。
- 整场提交前可以返回被跳过的题。
- 整场提交前可以修改已回答题目，保存后覆盖旧答案。
- 存在未回答题目时，提交整场必须二次确认。
- 面试完成后所有回答锁定，不能重新回答或修改。

离开保护：

- 存在尚未保存的文本时，页面内跳转或关闭页面需要提示。
- 已保存答案和计时状态刷新后可恢复。
- 网络断开时保留本地草稿，恢复后由用户确认提交。

### 9.11 面试报告

报告包括：

- 总分和完成状态。
- 各题得分横向条形图。
- 优势总结。
- 优先改进方向。
- 下一步训练建议。
- 逐题原问题、用户回答、得分、点评、参考答案和证据。
- 报告生成失败或尚未生成时的恢复操作。
- 浏览器打印和导出 PDF。

移动端图表和逐题内容使用单列布局。打印样式隐藏导航和非报告操作。

### 9.12 任务中心

- 展示任务类型、关联对象、状态、进度、创建时间和完成时间。
- 第一阶段主要展示简历解析任务。
- 状态包括等待中、处理中、成功、失败。
- 失败任务显示错误摘要和重试入口。
- 支持按状态筛选。
- 为后续 ASR 等异步任务预留任务类型。

### 9.13 设置

- 个人资料：显示名称和邮箱。
- 外观：浅色、深色、跟随系统。
- 安全：修改密码。
- 账户：退出登录。
- 暂不提供注销账户，除非后端补充对应能力。

## 10. 前端技术方案

### 10.1 推荐技术栈

| 能力 | 选型 |
| --- | --- |
| React 框架 | Next.js App Router |
| UI 核心 | React + TypeScript |
| 样式 | Tailwind CSS |
| 基础组件 | shadcn/ui |
| 服务端状态 | TanStack Query |
| 表单 | React Hook Form |
| 数据校验 | Zod |
| 主题 | next-themes + CSS Variables |
| API 类型 | goctl 生成的 TypeScript 类型/SDK |
| 单元测试 | Vitest + Testing Library |
| 端到端测试 | Playwright |
| 包管理 | pnpm |

Next.js 继续作为 React 应用框架，原因如下：

- 官网需要良好的 SEO 和首屏表现。
- App Router 适合公共区、登录区和产品区分层。
- 可使用布局、错误边界、加载状态和服务端渲染能力。
- 无需为了“以 React 为核心”而迁移到纯 Vite SPA。

### 10.2 状态管理原则

- TanStack Query 管理 API 数据、缓存、失效、轮询和请求状态。
- React Hook Form 管理表单状态。
- Zod 统一前端输入校验和错误信息。
- 页面短期交互优先使用组件状态或 reducer。
- 不默认引入 Redux/Zustand；只有出现明确的跨页面客户端状态后再评估。
- 面试的权威状态必须来自服务端，本地只保存未提交草稿。

### 10.3 API 层

- 页面和组件不得直接散落调用 `fetch`。
- 生成 SDK 外包一层业务 API Client，用于：
  - 认证信息注入。
  - 错误格式归一化。
  - 请求取消和超时。
  - 上传进度。
  - 401 统一处理。
  - 请求追踪 ID。
- Query Key 按资源统一定义。
- API 类型不得在页面中重复手写。

## 11. 通用交互规范

### 11.1 加载状态

- 页面首次加载使用骨架屏。
- 按钮提交使用按钮内 loading，不让整个页面闪烁。
- 超过 2 秒的生成/解析操作显示阶段信息。
- 异步任务离开页面后仍可在任务中心追踪。

### 11.2 空状态

空状态必须包含：

- 当前没有什么内容。
- 为什么需要该内容。
- 用户下一步可以执行的主操作。

### 11.3 错误状态

- 表单错误显示在字段附近。
- 页面加载失败提供重试。
- 权限错误跳转登录并保留返回地址。
- 网络断开显示全局提示。
- 后端原始错误不得直接完整暴露给用户。

### 11.4 成功反馈

- 创建、保存、删除等操作使用轻量 Toast。
- 对流程关键的成功结果跳转到对应详情页。
- 不用 Toast 替代重要页面状态。

### 11.5 危险操作

删除简历、JD、题集前必须显示确认弹窗，说明影响范围。按钮使用明确文案，例如“删除这份简历”，避免只写“确认”。

## 12. 响应式设计

建议断点：

- 移动端：小于 768 px。
- 平板/小桌面：768–1199 px。
- 桌面端：1200 px 及以上。

要求：

- 页面最小支持宽度 320 px。
- 移动端不得产生横向滚动。
- 数据表格在移动端转换为卡片或摘要列表。
- 弹窗在移动端转换为底部抽屉或全屏页面。
- 触控目标不小于 44 × 44 px。
- 固定底部操作区必须考虑安全区域。
- 面试页输入框在手机键盘弹出后仍能看到主要操作。

## 13. 可访问性

- 所有操作可使用键盘完成。
- 焦点状态清晰可见。
- 表单字段具有真实 label 和错误关联。
- 图标按钮提供可访问名称。
- 颜色不是表达状态的唯一方式。
- 正文和关键控件满足 WCAG AA 对比度。
- 尊重 `prefers-reduced-motion`。
- 弹窗打开后锁定焦点，关闭后恢复到触发元素。

## 15. 后端 TODO

下面接口是完成本规格所必需或建议补充的后端能力。最终命名以 `.api` 契约评审为准。

### 15.1 P0：阻塞核心面试体验

#### 面试列表

```http
GET /api/v1/interviews
```

建议支持：

- `status`
- `page`
- `page_size`
- `sort`

返回面试摘要、回答进度、题目数量和报告总分。

#### 保存指定题目的回答

```http
PUT /api/v1/interviews/:id/turns/:ordinal/answer
```

规则：

- 面试为 active 时允许首次回答和覆盖回答。
- 面试 completed 后拒绝修改。
- 返回更新后的 turn 或完整 session。

#### 跳过指定题目

```http
POST /api/v1/interviews/:id/turns/:ordinal/skip
```

规则：

- 记录 `skipped_at`。
- 提交答案后清除跳过状态。
- 面试完成后拒绝操作。

#### 完成整场面试

```http
POST /api/v1/interviews/:id/complete
```

请求中可包含用户是否确认存在未回答题。完成后锁定所有回答，并允许生成报告。

#### 服务端计时字段

面试会话建议增加：

- `started_at`
- `completed_at`
- `duration_seconds`
- `question_duration_seconds`

面试题轮次建议增加：

- `started_at`
- `skipped_at`
- `time_spent_seconds`

`GET /interviews/:id` 必须返回足以让前端在刷新后恢复计时的信息。

### 15.2 P0：阻塞已确认的资源管理页面

#### JD 详情、更新和删除

```http
GET    /api/v1/job-descriptions/:id
PATCH  /api/v1/job-descriptions/:id
DELETE /api/v1/job-descriptions/:id
```

#### 简历更新、删除和重新解析

```http
PATCH  /api/v1/resumes/:id
DELETE /api/v1/resumes/:id
POST   /api/v1/resumes/:id/reparse
```

删除简历前需要校验其关联题集和面试，并返回可理解的冲突信息。

#### 题集列表、详情、更新和删除

```http
GET    /api/v1/question-sets
GET    /api/v1/question-sets/:id
PATCH  /api/v1/question-sets/:id
DELETE /api/v1/question-sets/:id
```

题目编辑可包含在题集 PATCH 中，或设计独立 turns/questions 接口。

#### 重新生成题集

```http
POST /api/v1/question-sets/:id/regenerate
```

需要明确是创建新版本还是覆盖原题集。建议创建新版本，保留旧面试的数据一致性。

### 15.3 P1：仪表盘和任务中心

#### 仪表盘摘要

```http
GET /api/v1/dashboard/summary
```

建议返回：

- 简历数量
- JD 数量
- 面试总数
- 最近平均分
- 分数趋势
- 高频改进方向
- 最近资源
- 进行中面试
- 活跃任务

#### 任务列表

```http
GET /api/v1/tasks
```

建议支持任务类型、状态、分页和时间排序。

#### 重试失败任务

```http

```

### 15.4 P1：用户与认证

#### 更新当前用户

```http
PATCH /api/v1/me
```

第一阶段至少支持修改显示名称。

#### 修改密码


#### 会话刷新与退出

```http
POST /api/v1/auth/refresh
```

正式产品建议使用短期 access token、refresh token 和 HttpOnly Secure Cookie，避免长期 JWT 只存储在 `localStorage`。在后端完成会话升级前，前端需要明确当前认证方案的临时性质。

## 16. 前后端协作约束

- 所有新增接口先修改 `backend/api/interviewmaster.api`。
- Go handler、OpenAPI 和 TypeScript SDK 从契约重新生成。
- 前端不得长期维护与契约重复的手写响应类型。
- 列表接口统一分页结构和空列表表达。
- 错误响应统一包含机器可读 `code`、用户可读 `message` 和可选 `details`。
- 时间统一使用 UTC RFC 3339，由前端按用户本地时间展示。
- 删除、完成面试等操作应保证幂等性或提供明确冲突错误。

推荐统一错误结构：

```json
{
  "code": "INTERVIEW_ALREADY_COMPLETED",
  "message": "本场面试已经完成，不能再次修改回答",
  "details": {}
}
```

## 20. 验收标准

满足以下条件后，本轮前端重构可视为完成：

- 未登录用户访问 `/` 时看到完整中文产品官网。
- 注册、登录、退出和鉴权跳转逻辑完整。
- 登录后所有确认页面均有独立路由，不再集中在单个页面。
- 用户能完成“简历 → JD → 题集 → 面试 → 报告”完整流程。
- 面试界面一次只展示一道题，同时显示单题和整场计时。
- 用户能在完成前跳过、返回和覆盖回答，完成后不能修改。
- 简历、JD、题集、面试和任务均有清晰的列表、详情或状态页面。
- 浅色和深色主题均通过视觉验收。
- 320 px 宽度下无横向滚动，移动端可以完成核心流程。
- 所有异步操作具有加载、成功、失败和空状态。
- 所有后端缺失能力均已实现，或在界面中明确禁用且有对应 TODO。
- TypeScript 不存在未解释的 `any`，lint、typecheck、测试和构建全部通过。
- 核心页面通过键盘操作和基本可访问性检查。

## 21. 暂待后续决策
