# AI 面试全流程辅助系统（InterviewMaster RAG）需求文档

> 状态：历史需求草稿。产品边界与技术选型以 [`技术方案_v1.md`](技术方案_v1.md) 为准；本文件将在下一阶段重写为正式需求文档。

## 1. 项目概述

### 1.1 项目背景

在求职过程中，候选人往往面临信息不对称、自我复盘不客观、以及面试题库针对性不足的问题。

### 1.2 项目目标

构建一个基于 RAG 架构的智能系统，利用候选人简历、面试记录以及互联网实时面试经验（面经），提供**个性化、深度批判、精准预测**的面试辅助。

## 2. 核心功能需求

### 2.1 模块一：面试记录深度复盘与批判（Interview Critique）

- **输入：** 用户的面试录音转文字（Transcript）、候选人简历、对应职位描述（JD）。
- **功能点：**
  - **面试官意图分析：** 解析面试官每个问题背后的侧重点（如：考察技术深度、团队协作、还是抗压能力）。
  - **多维度评分：** 针对候选人的回答给出逻辑性、完整性、技术准确度评分（0-100）。
  - **批判性反馈：** 指出回答中的冗余、模糊或逻辑漏洞。
  - **话术优化（Golden Answer）：** 结合简历中的真实项目细节，生成一份更流畅、更具细节（Star法则）的参考回答。

### 2.2 模块二：基于简历的精准押题（Resume-Based Q&A Prediction）

- **输入：** 用户上传的 PDF/Word 简历。
- **功能点：**
  - **简历知识图谱化：** 提取简历中的技术栈、项目亮点、职责关键词。
  - **考点权重评估：** 分析简历中哪些点最容易被面试官“挑战”（例如：项目中的高并发处理、过时的技术栈、或者是空白期）。
  - **模拟押题库：** 针对每个项目生成 3-5 个由浅入深的追问（Deep Dive Questions）。

### 2.3 模块三：全网面经自动化检索（Company-Specific Intel）

- **输入：** 目标公司名称、目标岗位关键词。
- **功能点：**
  - **面经爬取/检索：** 从知识库（或通过搜索 API 检索牛客网、知乎、LeetCode 等）获取近半年的面经。
  - **高频问题聚类：** 自动归纳该公司的面试风格（如：偏重算法、偏重八股、还是偏重场景设计）。
  - **实时问题更新：** 提取最新的面试原题并存入本地向量数据库。

## 3. 技术架构设计 (RAG-Focused)

### 3.1 数据层（Data Ingestion）

- **简历/记录：** 结构化处理（Unstructured 库），存入用户个人向量空间。
- **外部面经：** 爬虫/API 获取 -> 清洗 -> 分块（Chunking） -> Embedding -> 存入公共向量库（Milvus / Pinecone / Chroma）。

### 3.2 检索层（Retrieval）

- **多路召回：** 结合 **语义检索**（Vector Search）和 **关键词检索**（BM25），确保能精准找到对应公司的特定岗位考题。
- **上下文压缩：** 只提取与当前简历项目相关的面经片段，减少 LLM 的 Token 消耗。

### 3.3 生成层（Generation）

- **Prompt Engineering：**
  - *角色设定：* “你是一位拥有 10 年经验的技术面试官和职业教练。”
  - *少样本学习（Few-shot）：* 提供优秀回答的范式。
- **LLM 选择：** 建议使用 GPT-4o 或 Claude 3.5 Sonnet（对逻辑批判和细节优化表现极佳）。

## 4. 非功能性需求


| **维度**   | **需求描述**                                         |
| -------- | ------------------------------------------------ |
| **隐私保护** | 候选人的简历和面试记录属于高度隐私，必须实现数据脱敏或本地存储选项。               |
| **响应速度** | 检索 + 生成的总时长应控制在 5-10 秒内，以保证复盘体验。                 |
| **准确性**  | 技术性回答必须引用简历中的真实数据，不得虚构项目经历（Hallucination Check）。 |


---

## 5. 用户交互流程（User Workflow）

1. **准备阶段：** 用户上传简历 -> 系统自动分析生成“简历核心考点图谱”。
2. **备战阶段：** 输入“目标公司” -> 系统从面经库检索相关问题 -> 结合简历生成“预测卷”。
3. **复盘阶段：** 面试结束后上传录音文字 -> 系统对比“参考回答”与“实际回答” -> 给出打分报告和改进版话术。

---

## 6. 待办事项与阶段规划 (Roadmap)

- **Phase 1 (MVP):** 实现简历解析与基于简历的 AI 押题功能。
- **Phase 2 (RAG Integration):** 搭建向量数据库，实现本地/在线面经的检索与回答。
- **Phase 3 (Optimization):** 引入语音转文字（ASR）模块，实现面试录音的一键导入与自动批判。
